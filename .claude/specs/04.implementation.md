Persistent context at `browser_profiles/<site>/`. `context.route("**/*")` aborts requests to hosts outside `allowed_hosts` ∪ {input host}; aborted requests are counted on `browser.blocked_requests`.
  - Depends on: T1, T3
  - Verify: `pytest tests/test_browser.py -q` (classify: job→`job_description`, apply_1→`form`, login→`login`, review→`review`; popup Apply switches `page`; a request to `127.0.0.2` is blocked and counted)

- [ ] **T5: Observe**

  - Verify: `pytest tests/test_observe.py -q` (apply_1 → 6 fields with correct kinds and options preview; `?many=1` → `truncated: true` and `approx_tokens ≤ 1500`; `suggested_next` on job → click Apply; on apply_1 → fill First Name; second call hits cache)

- [ ] **T6: Helpers with expectations and submit guard**

### Phase 2 — Harness

- [ ] **T10: Steps file manager**
  - Creates: `agent/steps_file.py`, `tests/test_steps_file.py`
  - Contract: `StepsFile(path, lock_path)` with `steps() -> list[StepInfo(name, index, source, locked)]`, `add(name, body) -> StepInfo` (validates `step_NN_<slug>`, next index, writes `def name(page, p):` + indented body, writes the §7.7 header on first add), `edit(old, new) -> StepInfo` (old occurs exactly once, inside the single unlocked step; else `LockedStepError`/`EditError`), `lock(name)`, `unlock(name)` (only one unlocked at a time), `undo_last_edit()`, `verify_lock_hashes()` (raises `TamperError`), `source_of(name)`.
  - Depends on: T7
  - Verify: `pytest tests/test_steps_file.py -q` (append order enforced; editing a locked step raises; undo restores exact bytes; tampering a locked function is detected)

- [ ] **T11: Tool schemas and dispatcher**

  - Depends on: T5, T8, T10
  - Verify: `pytest tests/test_tools.py -q` (`read_file("core/submit.py")` → error; `read_file("core/helpers.py")` returns signatures only; `add_step` with a bad name → error; schemas validate against the OpenAI function JSON shape)

- [ ] **T12: LLM client with stable prefix and fallback parsing**

  - Contract: `LLM(settings)` with `call(task: TaskBlock) -> ToolCall` where `TaskBlock` holds `observe`, `done_steps`, `profile_keys`, `last_notes`, `last_error`, `instruction`, `fix_source`; `build_messages(task) -> list[dict]` such that `messages[0]` (system) is byte-identical across calls for the same example file; prompt trimming order from `03` §6.3 until `approx_tokens ≤ PROMPT_TOKEN_CAP`; parses `tool_calls`, falls back to a fenced-JSON block, raises `NoToolCall` otherwise; records `usage` tokens (or chars/4 with `tok_est=True`). `example_steps.py` is a 12-step file that passes `run_checks` on the fixture.
  - Depends on: T11
  - Verify: `pytest tests/test_llm_prompt.py -q` (system message identical across two tasks; a 120-field observe gets trimmed under the cap; fenced-JSON fallback parses; `example_steps.py` passes `lint` and `sandbox_check`)

- [ ] **T13: Fake LLM for tests**

  - Contract: `FakeLLM(script: list[ScriptItem])` implementing `call(task) -> ToolCall`; each `ScriptItem` matches on `(task.instruction_kind, task.observe.suggested_next.targets)` and returns a tool call; unmatched → `NoToolCall` (so tests fail loudly). Ships the nine scripts of `03` §8.2.
  - Depends on: T12
  - Verify: `python -c "import tests.fake_llm as f; assert len(f.SCRIPTS)==9"`

- [ ] **T14: Runner: `run_step` and `run_checks`**

  - Contract: `run_step(browser, steps_file, name, profile, log) -> StepResult` (§7.5.3): `ctx.begin(prev_url, prev_snapshot)` → import the step function from the current file (fresh module load) → execute → `verify_expectations` → classify page → `retry_mode` per D4; `run_checks(company, browser_factory, profile, log) -> CheckResult`: lint → sandbox → each sample in `tests.yaml` from `goto(url)` through all steps to `review`, asserting `expect`; stops at first failure; never calls `submit`.
  - Depends on: T7, T10, T4
  - Verify: `pytest tests/test_runner.py -q` (`example_steps.py` passes `run_checks` on the fixture with 2 sample URLs; a deliberately broken step 4 returns `FAIL` with `stage=fill`, `step=step_04_phone`, `error` ≤ 20 lines; `retry_mode` is `in_place` when the page did not change)

- [ ] **T15: Build loop state machine**

  - Depends on: T13, T14

## 12. Acceptance criteria

Each item names the check that proves it.

- [ ] AC1. `scripts/check.ps1` exits 0 (ruff + safety tests + full `pytest`) in under 2 minutes without GPU or network. (T18)
- [ ] AC2. All nine fixture scripts in `tests/test_loop_fixture.py` pass, including phone-fix, regression-undo, limits, submit-guard, login-stop, popup-apply, token-cap, masking. (T15)
- [ ] AC3. `python -m agent test hcltech` prints `PASS n/n` with n ≥ 2 samples, each reaching `review` with the resume attached and no required field empty. (T19)
- [ ] AC4. `python -m agent test capgemini` prints `PASS 3/3`. (T20)
- [ ] AC5. For both live builds, `report.html` shows `rounds_total ≤ 40`, median `tries_per_step ≤ 2`, `fix_locality_violations == 0`, `regressions_open == 0`, `tok_in` p95 ≤ 3,500, `tok_out` max ≤ 300, build tokens ≤ 150k, wall-clock ≤ 20 min excluding human waits. (T19, T20)
- [ ] AC6. HCLTech `first_try_pass_rate ≥ 0.6`; Capgemini (with HCLTech example) `≥ 0.8`. (T19, T20)
- [ ] AC7. Zero `ForbiddenAction` submit presses, zero blocked-host requests originating from steps, zero `[redacted line]` or profile values in any `actions.jsonl`, `actions.md`, `report.html`, or prompt dump across all runs. (T16 scan, T18)
- [ ] AC8. `observe` payloads never exceed 1,500 tokens (chars/4) on fixture or live pages; truncation is flagged. (T5, T19 logs)
- [ ] AC9. Every generated `steps.py` passes `lint` and all six `sandbox_check` rules; `steps.lock.json` hashes match; tampering is detected. (T7, T10)
- [ ] AC10. The build path never imports `core.submit`; `MODE=build` makes `submit()` raise. (T9)
- [ ] AC11. Login or CAPTCHA pages stop the loop with `ask_human` and resume after the human acts, using the persistent browser profile. (T15 fixture script 6; T19 live)
- [ ] AC12. The dummy profile is the only profile used; the loader rejects resume paths outside `profiles/`. (T2)
- [ ] AC13. Both manifests carry `url_patterns`, `application_system: successfactors`, `allowed_hosts`, `version`, `built_with`; `status` is `reviewed` only by human edit. (T19, T20)
- [ ] AC14. Benchmark baselines exist for both companies and the latency baseline is recorded. (T21)
