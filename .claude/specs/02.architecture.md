## 5. Data specification

This is not a training project; "data" here means the inputs the loop observes and the artifacts it produces. All of it is small, local, and per-run.

### 5.1 Sources & access

| Data | Source | Access | Refresh |
|---|---|---|---|
| Job URLs (build input + test samples) | Human pastes; stored in `fillers/<company>/tests.yaml` | file | manual; failing real-run URLs appended later (repair mode) |
| Page observations | Live site via Playwright, trimmed by `core/observe.py` | in-memory + cached to `runs/<company>/<ts>/probe/<sha1>.json` | per URL + page state; re-observed on retry only for the failing step |
| Candidate profile (dummy) | `profiles/dummy.yaml` + `profiles/dummy_resume.pdf` (generated) | `core/profile.py` | static |
| Candidate profile (real, later) | `profiles/real.yaml` + real resume PDF, git-ignored | same loader | only when manifest `status: reviewed` and `--profile real` |
| Site logins | Human types them once into the persistent browser profile `browser_profiles/<site>/` | never read by code | per site |
| Worked example | `agent/prompts/example_steps.py` (fixture-based), then `fillers/hcltech/steps.py` once reviewed | `read_file` tool and prompt prefix | per build |

### 5.2 Schemas & volume

- **Observation** (§7.4): ≤ 40 fields, ≤ 8 options per field preview, ≤ 1,500 tokens. Tens per build.
- **Profile** (`core/profile.py`, pydantic model `Profile`): the keys below are the full v1 contract. Steps reference them as `p.<key>` or `p.answers["<key>"]`.

```yaml
# profiles/dummy.yaml  (all values intentionally fake; example.com is reserved for tests)
first_name: Test
last_name: Candidate
email: test.candidate@example.com
phone: "+91 90000 00000"
phone_country_code: "+91"
country: India
city: Pune
current_title: SAP BTP Consultant
total_experience_years: 5
notice_period_days: 30
current_ctc: "0"
expected_ctc: "0"
highest_degree: B.Tech
graduation_year: 2019
skills: [SAP BTP, CAP, Fiori, Python]
linkedin: https://www.linkedin.com/in/example
resume: profiles/dummy_resume.pdf
answers:
  willing_to_relocate: "Yes"
  work_authorization_india: "Yes"
  sponsorship_required: "No"
```

- **Action log**: one JSON line per tool call (§7.6); 50–300 lines per build.
- **Steps file**: one Python function per action; 10–40 functions per company.

### 5.3 Splits, labeling, quality

- There is no training split. The equivalent of a held-out set is `tests.yaml`: the step loop builds against **sample 1** only; `run_checks` must then pass on **all** samples (≥ 2, target 3). Passing on samples the loop never saw is the generalization check ("same code for the same company").
- Labels are produced by the harness, not humans: each helper call's expectation (§7.5) is the ground truth for PASS/FAIL. The human only reviews the final diff and report.
- Known quality gaps: (a) HCLTech currently has 1 sample URL (Q5); (b) whether sample postings share an identical form is assumed, not verified, until `run_checks` says so.

### 5.4 Drift

- **Site drift**: company changes its form. Detected when a previously passing `steps.py` fails `run_checks`. Response (post-v1 repair mode): run saved steps to the failing one, fix only it, add the failing URL to `tests.yaml`.
- **Model/prompt drift**: a prompt or model change silently makes builds worse. Detected by `python -m agent bench <company>` (from-scratch rebuild) comparing rounds, tokens, first-try rate against the stored baseline in `runs/<company>/bench/`.

### 5.5 Governance (PII, secrets, retention)

- Dummy profile only until `status: reviewed` (D6). The loader rejects a `resume` path outside `profiles/`.
- Logs, reports, prompts, and generated code never contain profile values, passwords, cookies, or tokens. `core/log.py` masks every profile value (`first_name=***`) and refuses to write any line matching a secret pattern (`password=`, `cookie:`, `Bearer `).
- Credentials are never loaded in `build`/`test` mode. The persistent browser profile holds the session; the code never reads it.
- Retention: `runs/` is git-ignored and may be deleted at any time; a filler keeps only a pointer to the run that built it.
- The real resume stored under `my-docs/` is never referenced by any config.

### 5.6 Versioning

- `fillers/<company>/manifest.yaml` carries `version` (int, bumped on every reviewed change) and `built_with` (model, harness version, run id).
- `steps.lock.json` stores a SHA-1 of each locked step's source so the harness can detect out-of-band edits and refuse to run on a tampered lock.
- Probe snapshots are content-addressed (`sha1` of the trimmed JSON) so identical page states are reused across tries.

### 7.3 LLM-facing tool contracts

Tools are presented to the model as OpenAI function-calling schemas generated from these signatures. All results are JSON, trimmed to the sizes stated. Any violation returns `{"ok": false, "error": "<one line>"}` and counts as a try.

| Tool | Arguments | Returns | Rules |
|---|---|---|---|
| `observe(scope?)` | `scope`: optional field label or section name to narrow the view on retry | `ObserveResult` (§7.4) | Cached by (url, dom-hash). `scope` forces a fresh, narrower observe. ≤ 1,500 tokens. |
| `read_file(path, start?, end?)` | repo-relative path; optional 1-based line range (max 80 lines) | `{"path", "lines": "start-end", "text"}` | Allowlist: `fillers/<current>/`, `core/helpers.py` (signatures only), `agent/prompts/example_steps.py`, and the current example steps file. Anything else → error. |
| `add_step(name, code)` | `name` must be `step_NN_<slug>` with `NN` = next index, `slug` `[a-z0-9_]{1,30}`; `code` = the function body lines only (no `def`) | `{"ok", "step": name, "index": NN, "lint": "ok" \| "<first error>"}` | Append-only. Harness wraps body in `def <name>(page, p):`. Runs `lint` + `sandbox_check` before accepting; a rejected step is not written. |
| `edit_file(path, old, new)` | `path` must be the current `steps.py`; `old` must occur exactly once and lie entirely inside the one **unlocked** step; `new` non-empty | `{"ok", "step": name, "lint": ...}` | Re-lint + sandbox after edit; failure reverts the edit and returns the error. Any attempt to touch a locked step → error `"step_03_email is locked"`. |
| `run_step(name)` | must be the newest or the currently unlocked step | `StepResult` (§7.5.3) | Executes only that step from the current browser state (D4), then verifies its expectations. |
| `run_checks(company?)` | defaults to current company | `CheckResult`: `{"status": "PASS"\|"FAIL", "stage": "lint"\|"sandbox"\|"fill", "sample": url\|null, "step": name\|null, "error": "<≤20 lines>", "passed": n, "total": m, "s": sec}` | Stages in order; stops at first failure. Never submits. |
| `note(text)` | ≤ 200 chars | `{"ok": true}` | Written to the log as actor `qwen`. The last 3 notes are fed back into the next prompt. |
| `ask_human(question)` | ≤ 300 chars | `{"answer": "<text>"}` (blocks) | Harness also calls this itself on login/captcha/limits. The loop pauses; browser stays open. |

The dispatcher (`agent/tools.py`) also enforces: one tool call per LLM turn; at most 1 `add_step` or 1 `edit_file` per round; `run_step` is invoked by the **harness** automatically after every accepted `add_step`/`edit_file`, so the model normally never needs to call it (it remains available for explicit re-runs).

### 7.4 ObserveResult (trimmed page view)

```json
{
  "page_kind": "form",                       // job_description | form | login | captcha | review | unknown
  "url": "https://careers.hcltech.com/talentcommunity/apply/180703/?locale=en_US",
  "title": "Apply - Engineer (Support & Operations)",
  "section": "Personal Information",         // nearest heading / wizard step label, if any
  "fields": [
    {"label": "First Name", "kind": "text", "required": true, "value": ""},
    {"label": "Country Code", "kind": "combobox", "required": true, "value": "", "options": ["India (+91)", "United Kingdom (+44)", "+6 more"]},
    {"label": "Phone Number", "kind": "text", "required": true, "value": ""},
    {"label": "Resume", "kind": "file", "required": true, "value": ""},
    {"label": "Willing to relocate", "kind": "radio", "required": true, "value": "", "options": ["Yes", "No"]}
  ],
  "buttons": ["Next", "Save"],
  "network": [{"m": "GET", "url": "careers.hcltech.com/talentcommunity/api/*", "st": 200}],
  "suggested_next": {"action": "fill", "targets": ["First Name"]},
  "snapshot": "3f9c…"
}
```

Field `kind` ∈ `text | textarea | select | combobox | file | radio | checkbox | date | button`. Phone is not a kind; the LLM sees `Country Code` (combobox) and `Phone Number` (text) as neighbours and writes one step for both.

**Trim rules** (`core/observe.py`): accessibility tree via `page.accessibility.snapshot(interesting_only=True)` plus a DOM pass for labels; drop hidden/`aria-hidden`/zero-size nodes, decorative nodes, duplicate labels within a section, and nodes from hidden wizard pages; keep only the active section when the page has a wizard; options truncated to 8 with `+N more`; `network` keeps only XHR/fetch to non-static paths, de-duplicated by host + path template, max 10. Hard caps: 40 fields, 1,500 tokens (chars/4); when exceeded, fields after the first empty required one are dropped and `"truncated": true` is set.

**`page_kind` classifier** (ordered rules, first match wins):
1. `captcha`: iframe `src` matches `recaptcha|hcaptcha|turnstile` or visible text matches `verify you are human|unusual traffic`.
2. `login`: a `password` input is visible, or URL path matches `/login|/signin|/auth/`.
3. `review`: a button matching `SUBMIT_RE = ^(submit|submit application|send application|apply now|complete application)$` (case-insensitive) is visible **and** no required empty field is visible.
4. `form`: ≥ 1 labelled input/select/file/radio/checkbox is visible.
5. `job_description`: a button/link matching `^apply( now)?$` is visible and rule 4 did not match.
6. `unknown`.

**`suggested_next`**: `job_description` → `{"action":"click","targets":["Apply"]}`; `form` → first required empty field (plus its immediate neighbour if the pair looks like code+number); no empty required fields → `{"action":"click","targets":["Next"|"Continue"|"Save and Continue"]}` whichever exists; `review` → `{"action":"stop"}`.

### 7.5 Step helpers and built-in checks (D3)

#### 7.5.1 Signatures (`core/helpers.py`)

```python
def click(page, text: str, *, expect: str = "any") -> None
    # expect: "navigation" (URL changes or a popup opens; popup becomes current page)
    #         "section"    (new fields appear that were not in the pre-step snapshot)
    #         "any"        (either of the above)
def fill(page, label: str, value: str) -> None
def pick(page, label: str, option: str) -> None          # native <select> or ARIA combobox / searchable list
def upload(page, label: str, path: str) -> None          # set_input_files; path must be under profiles/
def check(page, label: str, option: str) -> None         # radio group or checkbox; option "Yes"/"No"/<label>
def wait_for(page, label: str, timeout_s: float = 10) -> None
```

Label matching order: `get_by_label(label, exact=True)` → `get_by_label(label)` (case-insensitive, `*`/`:` stripped) → `get_by_role(<kind>, name=label)` → nearest-text fallback within the active section. If more than one match remains, the helper raises `AmbiguousLabel("<label>: 2 matches — 'Phone Number', 'Alternate Phone Number'")`.

Every helper auto-waits (visible + enabled, 10 s) and raises `HelperError` with a one-line, actionable message on failure. For `pick`, the message lists the closest option texts (`no option '+91'; options look like 'India (+91)', 'Indonesia (+62)'`), which is exactly what the LLM needs for a minimal fix.

**Submit guard**: in `MODE in {build, test}` `click` raises `ForbiddenAction` when `text` matches `SUBMIT_RE`. `upload` raises if `path` is outside `profiles/`.

#### 7.5.2 Expectations

Each helper appends to the thread-local `StepContext.expectations`:

| Helper | Expectation | Verified by |
|---|---|---|
| `click(expect="navigation")` | `PageChanged(prev_url)` | URL differs or a popup page became current |
| `click(expect="section")` | `NewFields(prev_snapshot)` | ≥ 1 labelled field not in the previous observe |
| `click(expect="any")` | either | either |
| `fill` | `ValueEquals(label, value)` | `input_value()` equals value (whitespace-normalised) |
| `pick` | `OptionSelected(label, option)` | selected option text (native) or displayed value (combobox) contains option |
| `upload` | `FileAttached(label, basename)` | basename text visible near the field, or `input_value()` of the file input ends with basename |
| `check` | `Checked(label, option)` | `aria-checked`/`checked` true on the matching option |
| `wait_for` | none | — |

A step with zero expectations is rejected by `sandbox_check` (it would be unverifiable).

#### 7.5.3 StepResult

```json
{"status": "PASS", "step": "step_04_phone", "checks": 2, "page_kind_after": "form", "url_after": "...", "s": 1.2}
{"status": "FAIL", "step": "step_04_phone", "failed_check": "OptionSelected('Country Code','+91')",
 "error": "HelperError: no option '+91'; options look like 'India (+91)', 'Indonesia (+62)'",
 "element_found": true, "page_kind_after": "form", "retry_mode": "in_place", "s": 1.2}
```

`error` is truncated to the last 20 lines. `retry_mode` is `in_place` or `replay` per D4.

### 7.6 Action log (`core/log.py`)

`runs/<company>/<timestamp>/actions.jsonl`, one object per line:

```json
{"t": "2026-10-16T10:02:46+05:30", "run": "hcltech/2026-10-16T10-02-11", "round": 7,
 "actor": "harness", "tool": "run_step", "in": "step_04_phone",
 "result": "FAIL · no option '+91'; options look like 'India (+91)'",
 "tok_in": null, "tok_out": null, "s": 1.2}
```

- `actor` ∈ `qwen | harness | human`. `tok_in`/`tok_out` are set only on `qwen` rows (from the server's `usage`, else chars/4 and flagged `"tok_est": true`).
- `in` and `result` are ≤ 200 chars after masking.
- `actions.md` is rendered from the same rows, one sentence per row, grouped by step.
- Masking: every string value from the loaded profile (and `basename(resume)`) is replaced by `***`; lines matching secret patterns are dropped and replaced by `"[redacted line]"`.
- Extra row types: `{"actor":"harness","tool":"undo","in":"step_04_phone","result":"regressed step_02_name · reverted"}`, `{"tool":"stop","result":"limit: 8 tries on step_05_resume"}`, `{"tool":"retry_mode","result":"replay"}`.

### 7.8 Sandbox rules for generated code (`core/checks.py::sandbox_check`)

AST-level, applied on every `add_step`/`edit_file` and as stage 2 of `run_checks`:

1. The only permitted import is `from core.helpers import click, fill, pick, upload, check, wait_for` (any subset). Any other `import`/`from` → reject.
2. Top-level statements: that import, and `def step_NN_<slug>(page, p):` functions only. No classes, no module-level code.
3. Inside a step: only expression statements that are calls to the six helpers, plus `wait_for`. No attribute access on `page` (so no `page.click`, no `page.evaluate`), no `eval`/`exec`/`open`/`__import__`, no `while`/`for`/`try`, no comprehensions, no lambda. `if` is not allowed in v1 (keeps steps linear and diffs tiny).
4. Allowed value expressions: string literals, f-strings, `p.<attr>`, `p.answers["<key>"]`, string concatenation.
5. Any string literal matching `SUBMIT_RE` as a `click` argument → reject with `"submit is not allowed"`.
6. Step names must be strictly increasing with no gaps; each step must contain ≥ 1 expectation-producing helper call.

Runtime guards (independent of AST): Playwright `context.route("**/*")` aborts requests whose host is not in `manifest.allowed_hosts` (plus the input URL's host); `upload` restricts paths to `profiles/`; `click` submit guard.

### 7.9 Infrastructure & configuration

- **Runtime**: Python ≥ 3.11 on Windows 11; `playwright` (Chromium), `pyyaml`, `pydantic`, `openai` (client only), `ruff` (lint), `pytest`, `jinja2` (report), `reportlab` (dummy resume generation).
- **Browser**: `launch_persistent_context(user_data_dir="browser_profiles/<site>/", headless=config.HEADLESS)`; default headed so the human can log in. One site = one profile directory; `<site>` = registrable domain of the apply host.
- **LLM server**: any OpenAI-compatible endpoint. Config via environment / `.env`:

| Var | Default | Meaning |
|---|---|---|
| `LLM_BASE_URL` | `http://127.0.0.1:8000/v1` | server |
| `LLM_MODEL` | `qwen3-coder-30b` | model name as served |
| `LLM_TEMPERATURE` | `0.1` | |
| `LLM_MAX_OUTPUT_TOKENS` | `400` | |
| `MODE` | `build` | `build \| test \| live` (live is post-v1) |
| `HEADLESS` | `false` | |
| `MAX_TRIES_PER_STEP` | `8` | hard stop |
| `MAX_ROUNDS_PER_COMPANY` | `60` | hard stop |
| `SAME_ERROR_SWITCH` | `3` | change approach after N identical errors |
| `SAME_ERROR_ASK` | `5` | ask human after N identical errors |
| `OBSERVE_TOKEN_CAP` | `1500` | |
