# fillers/

One folder per company, in a fixed format so any filler can be loaded, tested and reused the same way.

```
fillers/<company>/
  manifest.yaml      company, application_system, url_patterns, allowed_hosts, locale, version, status, built_with
  steps.py           generated by the agent: one function per browser action, append-only, passing steps locked
  steps.lock.json    sha1 + status per step (the harness refuses to run on a tampered lock)
  tests.yaml         sample job URLs the filler must pass (>= 2 before a filler can be reviewed)
```

## Commands

```
python -m agent build <job_url> [--company X] [--profile profiles/dummy.yaml] [--example fillers/hcltech/steps.py] [--headless] [--llm real|fake:<script>]
python -m agent test <company>                  # lint -> sandbox -> every step on every sample; prints PASS n/n or the first failure
python -m agent bench <company> [--no-example] [--no-suggest] [--heuristic]   # from-scratch rebuild into runs/<company>/bench/
python -m agent report runs/<company>/<ts>      # regenerate report.html from the action log
```

## Review step (decision D10)

The harness never sets `status: reviewed`. After `python -m agent test <company>` prints `PASS n/n`, open
`runs/<company>/<ts>/report.html`, read the diff and the flags, and edit `manifest.yaml` by hand:

```yaml
status: reviewed
```

Only a reviewed filler may later be run with a real profile. Test fills use `profiles/dummy.yaml` and never press Submit.
