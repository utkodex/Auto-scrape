## 1. Preconditions & setup

- **Environment**: Windows 11, Python ≥ 3.11 on `PATH` (`python --version`), PowerShell and Git Bash available. Create and use a virtualenv: `python -m venv .venv; .venv\Scripts\Activate.ps1`.
- **Dependencies** (declared in T1 `pyproject.toml`): `playwright`, `pyyaml`, `pydantic>=2`, `pydantic-settings`, `openai`, `ruff`, `pytest`, `jinja2`, `reportlab`, `python-dotenv`. Chromium via `playwright install chromium` (one-time, ~150 MB download; the only network use in Phases 0–2).
- **Data & credentials**: none for Phases 0–2. Phase 3 needs: the Qwen3-Coder-30B OpenAI-compatible server reachable at `LLM_BASE_URL`, a human at the keyboard to log in to each career site once, and the live job URLs listed in the specs. No credentials are ever placed in files; logins happen in the persistent browser profile only.
- **Baseline state**: the repo is not a git repository yet. T1 runs `git init` and commits the scaffold so every later task is reversible with `git checkout -- <path>` / `git revert`.
- **Verification tooling**: `pytest` and `ruff` (installed by T1); `scripts/check.ps1` (T18) runs the whole offline gate. There is no MLflow/tracing stack; the trace equivalent is `runs/<company>/<ts>/actions.jsonl` and `report.html`, which Phase 3 Verify lines inspect.
- **Safety invariants that hold from T6 onward** (never relax while executing): `MODE=build` by default; `core/submit.py` is never imported by `agent/` or `core/`; the dummy profile is the only profile; no real resume path is ever written into any file under version control.

### Phase 1 — Core runtime (offline)

- [ ] T4: Browser wrapper with persistent profile, popup tracking, host allowlist, page classifier
  - **Goal**: one object that owns the live browser and knows which tab is current and what kind of page it shows.
  - **Creates**: `core/browser.py`, `tests/test_browser.py`
  - **Steps**:
    1. `class PageKind(str, Enum)`: `job_description, form, login, captcha, review, unknown`.
    2. `class Browser(site: str, allowed_hosts: list[str], headless: bool, profiles_root: Path = Path("browser_profiles"))`: `launch_persistent_context(user_data_dir=profiles_root/site)`; `context.on("page", ...)` appends new pages and sets `self.page` to the newest; `context.route("**/*", handler)` aborts requests whose host does not match `allowed_hosts` (glob, `*.successfactors.com`) or the host of the last `open()` URL, incrementing `self.blocked_requests` and appending `(url)` to `self.blocked`.
    3. `open(url) -> Page`, `goto(url)`, `screenshot(dir: Path) -> Path` (timestamped PNG), `close()`.
    4. `classify(page) -> PageKind` implementing the six ordered rules of `02.architecture.md` §7.4 (`SUBMIT_RE` lives here and is imported by helpers); `detect_system(page) -> str` using the §7.7 markers over page URL and the URLs of requests seen so far.

  - **Depends on**: T1, T3
  - **Verify**: `pytest tests/test_browser.py -q` → pass.
  - **On failure**: popup tracking is the usual culprit; assert `context.pages[-1]` after `expect_page`.

- [ ] T5: Observe: trimmed accessibility view, suggested next action, snapshot cache
  - **Goal**: the ≤ 1,500-token page view the LLM sees.
  - **Creates**: `core/observe.py`, `tests/test_observe.py`
  - **Steps**:
    1. Pydantic models `Field(label, kind, required, value, options: list[str] | None)`, `NetworkCall(m, url, st)`, `SuggestedNext(action, targets)`, `ObserveResult(page_kind, url, title, section, fields, buttons, network, suggested_next, snapshot, truncated=False)` with `.to_json()` (compact separators).
    2. `approx_tokens(text_or_obj) -> int` = `len(json)//4`.
    3. `observe(browser, scope=None, cache_dir=None, cap_tokens=1500) -> ObserveResult`: wait for `networkidle` (3 s max); DOM pass with `page.evaluate` collecting labelled controls (`label[for]`, `aria-label`, `aria-labelledby`, wrapping `<label>`), their kind (`text|textarea|select|combobox|file|radio|checkbox|date|button`), `required`, current value, and for `select`/`combobox`/`radio` the first 8 option texts plus `+N more`; drop hidden/`aria-hidden`/zero-size nodes and duplicate labels within the active section; `buttons` = visible button/link texts; `network` = XHR/fetch seen via `page.on("request")` since the last navigation, de-duplicated by host + path template (numeric segments → `*`), max 10; `section` = nearest visible `h1–h3` / wizard step label; `scope` keeps only fields whose label or section contains it.
    4. `suggested_next` per §7.4 (first required empty field; pair with its neighbour when labels look like `Country Code`/`Phone Number`; else Next/Continue/Save and Continue; `job_description` → Apply; `review` → `stop`).
    5. Trim to `cap_tokens` in the §6.3 order (`network` → options to 4 → drop non-required fields after the target); set `truncated=True`; assert `approx_tokens(result) <= cap_tokens`.
    6. Cache: `snapshot = sha1(url + json of fields/buttons)`; write `cache_dir/<snapshot>.json`; return cached result when the DOM hash is unchanged and `scope is None`.
    7. Tests: `apply_1` → 6 fields with the right kinds and `options[0] == "India (+91)"` for Country Code; `?many=1` → `truncated` and `approx_tokens <= 1500`; `job.html` → `suggested_next.action == "click"` and `targets == ["Apply"]`; `apply_1` → `fill` / `["First Name"]`; second call returns a cached object (same `snapshot`, file exists).
  - **Contract**: JSON shape exactly as `02.architecture.md` §7.4.
  - **Depends on**: T4
  - **Verify**: `pytest tests/test_observe.py -q` → pass, including the `<= 1500` assertion.
  - **On failure**: print `approx_tokens` per trim stage; the 120-field page must trim below the cap, otherwise the trim order is wrong.

- [ ] T6: Step helpers with built-in expectations and the submit guard
  - **Goal**: the six deterministic calls generated steps are allowed to make, each recording the check that proves it worked.
  - **Creates**: `core/helpers.py`, `tests/test_helpers.py`
  - **Steps**:
    1. Exceptions `HelperError`, `AmbiguousLabel(HelperError)`, `ForbiddenAction(HelperError)`.
    2. `@dataclass` expectations `PageChanged(prev_url)`, `NewFields(prev_snapshot)`, `ValueEquals(label, value)`, `OptionSelected(label, option)`, `FileAttached(label, basename)`, `Checked(label, option)`; `class StepContext` (thread-local via `contextvars`) with `expectations: list`, `prev_url`, `prev_snapshot`, `mode`; `begin(prev_url, prev_snapshot, mode)`, `end() -> list`.
    3. `_locate(page, label, kinds) -> Locator`: `get_by_label(exact=True)` → `get_by_label` after stripping `*`/`:` and case-folding → `get_by_role(kind, name=label)` → nearest-text fallback; raise `AmbiguousLabel("<label>: N matches — 'a', 'b'")` when > 1.
    4. `click(page, text, *, expect="any")`: if `ctx.mode in {"build","test"}` and `SUBMIT_RE.match(text)` → `ForbiddenAction("submit is not allowed")`; `get_by_role("button"|"link", name=text)`; on click use `context.expect_page()` with a short timeout to catch popups (then set `browser.page` via a callback registered on the context); append `PageChanged`/`NewFields` per `expect`.
    5. `fill(page, label, value)`: `_locate` → `fill` → append `ValueEquals`.
    6. `pick(page, label, option)`: if the element is a native `<select>` → `select_option(label=option)`; else open the combobox, type `option`, click the `role=option` whose text contains `option`; on no match raise `HelperError(f"no option '{option}'; options look like {', '.join(closest3)}")` using `difflib.get_close_matches` over the visible option texts; append `OptionSelected`.
    7. `upload(page, label, path)`: reject paths not under `<repo>/profiles/` with `ForbiddenAction`; `set_input_files`; append `FileAttached(label, basename)`.
    8. `check(page, label, option)`: radio group → click the option whose label matches; checkbox → check when `option` in {"Yes","true",label}; append `Checked`.
    9. `wait_for(page, label, timeout_s=10)`: `_locate(...).wait_for(state="visible")`; no expectation.
    10. All helpers: 10 s auto-wait for visible+enabled; wrap Playwright `TimeoutError` into `HelperError("<label>: not found/visible after 10s")`.
    11. Tests on the fixture: each helper records exactly one expectation of the right class; `pick(page,"Country Code","+91")` raises `HelperError` whose message contains `India (+91)`; in build mode `click(page,"Submit application")` raises `ForbiddenAction` and the page URL is unchanged; `upload(page,"Resume","my-docs/x.pdf")` raises `ForbiddenAction`; `AmbiguousLabel` on a page with two "Phone" labels (add a tiny extra fixture page `tests/fixtures/sf_like/ambiguous.html`).
  - **Contract**: signatures and expectation table in `02.architecture.md` §7.5.1–7.5.2.
  - **Depends on**: T2, T4
  - **Verify**: `pytest tests/test_helpers.py -q` → pass.
  - **On failure**: if the combobox test is flaky, add `wait_for(state="visible")` on the listbox before typing; never loosen the submit test.

### Phase 2 — Harness (offline)

- [ ] T10: Append-only steps-file manager with locking, undo, and tamper detection
  - **Goal**: the only writer of `steps.py`, enforcing "locked steps never change".
  - **Creates**: `agent/steps_file.py`, `tests/test_steps_file.py`
  - **Steps**:
    1. `STEP_NAME_RE = r"^step_(\d{2})_([a-z0-9_]{1,30})$"`; `@dataclass StepInfo(name, index, source, locked)`; exceptions `StepNameError`, `LockedStepError`, `EditError`, `TamperError`.
    2. `class StepsFile(path: Path, lock_path: Path)`: on first `add` writes the §7.7 header line `from core.helpers import click, fill, pick, upload, check, wait_for`; `steps()` parses with `ast` and returns `StepInfo`s in file order; `add(name, body) -> StepInfo` validates the name, requires `index == len(steps)+1`, requires no unlocked step, writes `def name(page, p):` + 4-space-indented body lines; `edit(old, new) -> StepInfo` requires `old` to occur exactly once in the file and entirely inside the single unlocked step's source, else `EditError`/`LockedStepError`; keeps `self._edit_history: list[(step, before_text)]` for `undo_last_edit()` which restores exact bytes; `lock(name)` records `{"sha1": sha1(source), "status": "locked"}` in `lock_path`; `unlock(name)` allowed only when nothing else is unlocked; `verify_lock_hashes()` raises `TamperError` naming the step whose source hash differs; `source_of(name) -> str`; `unlocked() -> str | None`.
    3. Tests: append order (adding `step_03` before `step_02` raises); editing a locked step raises `LockedStepError`; editing text spanning two steps raises `EditError`; `undo_last_edit` restores byte-identical content; editing the file by hand then `verify_lock_hashes()` raises `TamperError`; only one unlocked at a time.
  - **Contract**: `02.architecture.md` §7.3 `add_step`/`edit_file` rules and `03.build-loop-and-eval.md` §6.4 invariants.
  - **Depends on**: T7
  - **Verify**: `pytest tests/test_steps_file.py -q` → pass.

## 4. Risks & rollback (execution-time)

- **Phase isolation**: every phase ends in a commit; roll back a task with `git checkout -- <files>` or `git revert <phase commit>`.
- **Fixture drift**: T6–T15 all depend on the T3 fixture; change the fixture only by adding query-flag variants, never by altering existing default behaviour.
- **Flaky browser tests**: use a session-scoped headless `Browser`; retry policy in tests is forbidden (a flaky helper will also be flaky for the model). Fix waits in `core/helpers.py` instead.
- **Live-phase stops**: a `STOP` or unanswered `ask_human` leaves `fillers/<company>/steps.py` with only locked, passing steps and a partial report; re-running `build` continues. To abandon a build, delete `fillers/<company>/steps.py` and `steps.lock.json`; `manifest.yaml` and `tests.yaml` stay.
- **Server trouble**: if the Qwen server returns malformed tool calls persistently, set `LLM_FORCE_JSON_MODE=1` (T12 fallback) and continue; if latency is far over budget, lower `OBSERVE_TOKEN_CAP` to 1,000 before changing prompts.
- **Never**: set `MODE=live`, point `--profile` at a real profile, or edit a locked step by hand during this plan.
